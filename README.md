# Smoke Free - 전국 금연구역 조회 서비스
- 공공데이터포털의 전국 금연구역 표준데이터 API로 시군구명을 검색해 금연구역 정보를 조회하는 웹페이지입니다.
- 이번 주에는 상세 검색 입력 폼(입력 검증, 조건부 입력, 제출 상태 처리)을 구현하고, 검색 조건을 브라우저에 저장하는 기능을 추가했습니다.

- GitHub 저장소: https://github.com/sjscjstk/UIUXProgramming
- 배포 페이지: https://sjscjstk.github.io/UIUXProgramming/

## 9주 추가·수정한 기능

### 1. 헤더·내비게이션·푸터 수정
- 로고 이미지가 들어간 헤더/푸터로 변경, 내비게이션에 상세 검색, 내 검색 정보 메뉴 추가
- 다크 모드 버튼을 헤더로 이동 (aria-pressed 상태 반영)

### 2. 상세 검색 폼
- 약관 동의 후 서비스 시작하기 → 시군구명 입력 → 아래 3단계 폼으로 진행합니다.
- 모든 입력 요소에 label을 연결했고, 도움말(field-help)·글자 수/조건 문구(field-status)·오류 문구(field-error)를 aria-describedby로 연결했습니다.

### 3. 조건부 입력
- 상세 시설 유형 조건 포함 체크 시 시설 유형 영역이 표시되고 라디오가 활성화됩니다.
- 체크 해제 시 영역이 숨겨지고 라디오(fieldset 포함)가 disabled로 비활성화됩니다. 초기 상태도 비활성화입니다.

### 4. 입력 검증과 피드백
- 입력하는 동안 n자 입력 · 2글자 이상 입력해 주세요. → ✓ n자 입력 · 입력 조건을 충족했어요.처럼 문구와 색으로 상태를 보여줍니다. (사용자 이름은 n / 10자 · ...)
- 오류가 표시된 뒤 올바르게 고치면 입력 즉시 오류 문구와 빨간 테두리(aria-invalid)가 해제됩니다.

### 5. 폼 제출 처리
- form의 submit 이벤트로 처리합니다. (finish-button은 type="submit")
- 조건을 충족하지 못하면 제출을 막고 1단계로 돌아가 오류 문구를 표시한 뒤 해당 입력창에 포커스를 줍니다.
- 제출 중에는 "검색 조건을 저장하는 중입니다..." 문구를 표시하고 버튼을 비활성화(disabled, aria-busy)하여 중복 제출을 막습니다.
- 성공하면 검색 조건을 localStorage에 저장하고 완료 화면과 공공데이터 검색 결과를 표시합니다. 내 검색 정보에서 저장 기록 확인, 내용 보기(모달), 검색 기록 취소/되돌리기가 가능합니다.
- 실패하면 입력 내용을 그대로 유지한 채 "저장하지 못했습니다..." 안내를 표시하고 버튼을 다시 활성화하여 재시도할 수 있습니다.
- 새 조건 설정하기는 입력값, 글자 수·오류 문구, 조건부 영역, 버튼 상태, 이전 검색 결과를 함께 초기화합니다.
- 검색 결과가 없으면 "해당하는 금연구역 데이터가 없습니다" 안내를 표시합니다.

## 실패 처리
1. 입력 조건 미충족
 - 처리 : 제출 차단, 1단계 이동, 오류 문구
 - 코드 위치 : planForm submit 이벤트
2. localStorage 저장 실패
 - 처리 : 입력 유지, 실패 안내, 재시도 가능
 - 코드 위치 : savePlans() 반환값 처리 (submit 이벤트)
3. localStorage 읽기 실패
 - 처리 : 빈 목록으로 처리
 - 코드 위치 : readPlans()의 try/catch

## 동작 확인 순서
1. 약관 동의 체크 → 서비스 시작하기 활성화 확인 후 시작합니다.
2. 빈 값 제출: 시군구명을 비운 채 상세 검색하기를 눌러 오류 문구가 나오는지 확인합니다.
3. 잘못된 값: a(영문·1글자), 관(1글자)을 차례로 입력해 오류 문구와 입력 중 상태 문구를 확인합니다.
4. 오류 수정: 관악구로 고치면 오류가 사라지고 ✓ 조건을 충족했어요가 표시되는지 확인합니다.
5. 사용자 이름에 1글자를 입력하고 검색 조건 선택하기를 눌러 오류를 확인하고, 2글자 이상으로 고치면 해제되는지 확인합니다.
6. 조건부 영역: STEP 02에서 상세 시설 유형 조건 포함을 체크/해제하며 영역 표시와 라디오 활성화/비활성화(개발자 도구에서 disabled 속성)를 확인합니다.
7. STEP 03에서 요약을 확인하고 정보 수정 / 조건 수정으로 돌아가도 값이 유지되는지 확인합니다.
8. 정상 제출: 검색 결과 저장 및 확인하기를 눌러 진행 문구와 버튼 비활성화, 이후 완료 화면·검색 결과·내 검색 정보 기록 추가를 확인하고, 새로고침 후에도 기록이 남는지 확인합니다.
9. 실패 처리: 개발자 도구 콘솔에 Storage.prototype.setItem = () => { throw new Error("test"); }를 입력한 뒤 제출해, 실패 안내가 뜨고 입력값이 유지되며 다시 누를 수 있는지 확인합니다. (새로고침하면 원래대로 돌아옵니다.)
10. 존재하지 않는 시군구명(예: 가나다구)으로 검색해 결과 없음 안내를 확인합니다.
11. 새 조건 설정하기를 눌러 입력값·문구·체크박스·버튼 상태가 모두 초기화되는지 확인합니다.
